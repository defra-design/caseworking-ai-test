Calculation runs

A line above the checks naming every time the rules have been run on a case, so a caseworker can see the current results and compare them with an earlier run.

The rules are re-run whenever something behind the application changes — most often when a land parcel's data is updated after the customer applied. A check that passed at submission can fail on a later run, so the caseworker needs to see both: what the rules say now, and what they said when the application came in.

Each run is listed with its date and time and whether it passed or failed overall. The run being shown is bold and not a link; the others are links. This is the same run history used inside the Calculations filter panel — use this standalone line on pages that have no filter panel.

Switching run

Each link sets a calcRun query parameter, which the Prototype Kit stores in session data, so the page can render either run from one template. The page heading, the "last run" line and every check follow the selected run.

What changes between runs

A check holds the figures for both runs, so the template picks the right set rather than the case needing two copies of every page:

  • The earlier run shows the figures as at submission. Every check passes and nothing is highlighted.
  • The latest run shows the current figures. Where a figure has changed it carries the changed-value highlight, and a check whose applied area now exceeds the available area shows a Failed tag with a "What to do" section.

Two forms

  • Standalone line — directly under the "Rules check last run" line, on pages with no filter panel.
  • Inside the filter panel — as the first row of the Calculations filter, where one exists, so the controls stay together.

When to use

  • When a case's rules have been run more than once and the caseworker may need to see what an earlier run said.
  • When results have changed because land data was updated after submission, so the caseworker can tell a new failure from a long-standing one.

When not to use

  • For a case with a single run — show the run date on its own, with no links.
  • As a general audit history. It lists rules runs only; case events belong on the Timeline.
  • For filtering what's on screen (use the Calculations filter).

Where does this occur

  • Large case calculations (40 parcels) — inside the filter panel; two runs, 5 fails in the latest.
  • Medium case calculations (5 parcels) — standalone line; two runs, 2 fails in the latest.
  • Real-case calculations (Golden Grange) — earlier form, where each run is its own page.
