Calculation runs

A small table under the page heading listing every time the rules have been run on a case, so a caseworker can see which run they are looking at and switch to another.

The rules are re-run whenever something behind the application changes — most often when a land parcel's data is updated after the customer applied. A check that passed at submission can fail on a later run, so the caseworker needs to see both: what the rules say now, and what they said when the application came in.

Switching run is a bigger decision than filtering, so the runs sit in their own always-visible table rather than inside the Calculations filter panel. Each row gives the run's date and time, a note (latest, or original at submission) and a result tag. The run being shown is shaded with a blue left edge and says Showing; every other run has a View this run link.

Switching run

Each View this run link sets a calcRun query parameter, which the Prototype Kit stores in session data, so the page can render either run from one template. The heading, the banner, the table's shaded row and every check follow the selected run.

What changes between runs

A check holds the figures for both runs, so the template picks the right set rather than the case needing two copies of every page:

  • The earlier run shows the figures as at submission. Every check passes and nothing is highlighted, so the failed-checks filter is not offered.
  • The latest run shows the current figures. Where a figure has changed it carries the changed-value highlight, and a check whose applied area now exceeds the available area shows a Failed tag with a "What to do" section.
  • The latest run's result tag counts its failed checks from the case data, so it stays right when the case is regenerated.

When to use

  • When a case's rules have been run more than once and the caseworker may need to see what an earlier run said.
  • When results have changed because land data was updated after submission, so the caseworker can tell a new failure from a long-standing one.

When not to use

  • For a case with a single run — show the run date on its own, with no table.
  • As a general audit history. It lists rules runs only; case events belong on the Timeline.
  • For filtering what's on screen (use the Calculations filter).

Where does this occur

  • Large case calculations (40 parcels) — two runs, 5 fails in the latest.
  • Medium case calculations (5 parcels) — two runs, 2 fails in the latest.
  • Real-case calculations (Golden Grange) — earlier form, where each run is its own page.
