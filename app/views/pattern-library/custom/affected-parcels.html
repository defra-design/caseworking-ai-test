Affected land parcels

A boxed list at the top of a review task naming the land parcels that task covers, taken from the same data as the calculations, so the list is always the real one.

Several review tasks only exist because of something found on specific land parcels — ponds to count, buildings to check, a Site of Special Scientific Interest to look up. The caseworker needs to know which parcels before they start, and the list has to match the checks on the Calculations page exactly. Naming the parcels in the task saves the caseworker cross-referencing, and stops the two screens disagreeing.

How the list is built

One include holds the rule for each kind of task and reads the case's parcel data — the same file the Application and Calculations pages import. A task asks for the kind it covers and gets back the parcel IDs:

  • ponds — parcels claiming a ponds action.
  • buildings — parcels claiming a buildings action.
  • sssi — parcels with an SSSI check.
  • any — every parcel in the case.

Because it reads the data rather than a hard-coded line, regenerating a case updates every task at once. A case with no data for that kind returns nothing, and the task falls back to its own line — so this can be added to a task without breaking the cases that don't have the data yet.

How the list is laid out

The IDs are a real list (<ul>) named by the heading, so a screen reader announces "Relevant land parcels, list, 6 items" rather than a table. The .app-lp-box and .app-lp-list rules in application.scss lay it out:

  • A full-width box with a 2px dark grey (#505a5f) border, 7.5px padding top and bottom, and 30px below it before the task's text.
  • A grid of ID-sized columns (6.4em) 20px apart, so the columns line up like a table. IDs never wrap.
  • At most 4 IDs a row, dropping to 3, 2 then 1 as the space narrows — no breakpoints, so it adapts wherever it sits.

Only the medium and large cases use the box. The other versions keep the one-line "Ref LPs: …" form.

When to use

  • On a conditional review task, where the task only exists for certain land parcels.
  • Where the same parcels appear as checks on the Calculations page, so the two must agree.

When not to use

  • On tasks covering the whole case (customer details, eligibility), where naming every parcel adds nothing.
  • To show parcel detail. It's a reference list, not a summary: areas, actions and figures belong on the Application and Calculations pages.
  • As the only way to reach the detail. On a long list, link the parcels to the filtered calculations instead of expecting the caseworker to search.

Where does this occur

  • Check that buildings on the land meet the action criteria — 28 parcels in the large case, 3 in the medium.
  • Check number and location of ponds — 12 parcels in the large case, 3 in the medium.
  • Check notice of planned activity for an SSSI — 6 parcels in the large case, 1 in the medium.
  • Check a ditch is not within a SSSI
